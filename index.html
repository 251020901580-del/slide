03 Phân tích Bài toán & Yêu cầu Hệ thống
Chương 1: Phân tích

📋 Yêu cầu Chức năng (Functional Requirements)

  • Quản trị & Xác thực: Đăng ký, đăng nhập tài khoản thủ thư (Librarian), mã hóa mật khẩu an toàn.
  • Quản lý Kho sách: Thêm, sửa, xóa, cập nhật số lượng, tìm kiếm đa tiêu chí và kiểm soát tồn kho khả dụng.
  • Quản lý Độc giả: Phân nhóm Sinh viên thường, Sinh viên ưu tiên, Giảng viên với hạn mức mượn riêng biệt.
  • Nghiệp vụ Mượn/Trả: Lập phiếu mượn nhiều đầu sách, tự động tính ngày quá hạn và phí phạt khi trả sách.
  • Báo cáo Thống kê: Thống kê tồn kho, phiếu đang mượn, phiếu quá hạn và doanh thu tiền phạt.

⚙️ Yêu cầu Kỹ thuật & Phi chức năng

  • Tính toàn vẹn dữ liệu: Ngăn chặn xóa sách hoặc độc giả đang có giao dịch mượn chưa hoàn tất (ItemInUseException).
  • Tính bền vững (Persistence): Dữ liệu lưu trữ xuống ổ đĩa dạng nhị phân (.dat), không mất khi tắt ứng dụng.
  • Tính mở rộng (Extensibility): Dễ dàng bổ sung đối tượng độc giả hoặc chính sách tính phạt mới nhờ OOP & Interface.
  • Độ tin cậy cao: Kiểm soát toàn bộ ngoại lệ đầu vào và nghiệp vụ qua hệ thống 13 lớp Exception tùy chỉnh.

10 Cài đặt Nghiệp vụ Mượn sách: BorrowService.java
Chương 3: Chi tiết Cài đặt Code
service/BorrowService.javaAtomic Transaction Logic
public class BorrowService implements Borrowable { @Override public BorrowTicket createBorrowTicket(String readerId, List<BorrowTicketDetail> details, LocalDate dueDate) throws LibraryException { Reader reader = readerRepo.findById(readerId); if (reader == null) throw new ReaderNotFoundException("Không tìm thấy độc giả!"); // 1. Kiểm tra tổng số sách đang mượn + sách mới <= hạn mức độc giả int currentBorrowed = countCurrentlyBorrowedBooks(readerId); int requestQty = details.stream().mapToInt(BorrowTicketDetail::getQuantity).sum(); if (currentBorrowed + requestQty > reader.getMaxBorrowLimit()) { throw new BorrowLimitExceededException("Vượt quá hạn mức mượn cho phép!"); } // 2. Kiểm tra tồn kho toàn bộ sách TRƯỚC khi trừ kho (đảm bảo tính nguyên tử) for (BorrowTicketDetail item : details) { Book book = bookRepo.findById(item.getBookId()); if (book == null) throw new BookNotFoundException("Sách không tồn tại!"); if (book.getAvailableQuantity() < item.getQuantity()) { throw new OutOfStockException("Sách không đủ số lượng: " + book.getTitle()); } } // 3. Cập nhật kho và lưu phiếu mượn details.forEach(d -> bookRepo.findById(d.getBookId()).decreaseAvailable(d.getQuantity())); bookRepo.saveAll(); BorrowTicket ticket = new BorrowTicket(IdGenerator.nextTicketId(ticketRepo.findAll()), ...); ticketRepo.add(ticket); return ticket; } }

🛡️ Điểm nổi bật trong Cài đặt

  • Tính Nguyên tử (Atomicity): Vòng lặp kiểm tra tồn kho chạy hoàn tất trước khi thực hiện decreaseAvailable(). Nếu cuốn sách thứ 2 trong phiếu hết hàng, cuốn thứ 1 sẽ không bị trừ kho sai lệch.
  • Đa hình tự động: Gọi reader.getMaxBorrowLimit() tự động áp dụng ngưỡng 5, 8 hoặc 10 cuốn tùy thuộc thực thể độc giả truyền vào.
  • Đồng bộ dữ liệu: Sau khi cập nhật kho sách, gọi ngay bookRepo.saveAll() và ticketRepo.add() để ghi xuống tệp .dat.
11 Cài đặt Tầng Dữ liệu: Generic BaseRepository<T>
Chương 3: Chi tiết Cài đặt Code
repository/BaseRepository.javaJava Generics & Serialization
public abstract class BaseRepository<T extends Serializable> { protected final String filePath; protected List<T> items; public BaseRepository(String filePath) { this.filePath = filePath; this.items = loadFromFile(); } @SuppressWarnings("unchecked") protected List<T> loadFromFile() { File file = new File(filePath); if (!file.exists()) return new ArrayList<>(); try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream(file))) { return (List<T>) ois.readObject(); } catch (Exception e) { throw new DataStorageException("Lỗi đọc file dữ liệu: " + filePath, e); } } public void saveAll() { File file = new File(filePath); if (file.getParentFile() != null) file.getParentFile().mkdirs(); try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream(file))) { oos.writeObject(items); } catch (IOException e) { throw new DataStorageException("Lỗi ghi file dữ liệu: " + filePath, e); } } }

💾 Lợi ích của Thiết kế Generic

  • Loại bỏ trùng lặp code (DRY): Toàn bộ 4 Repository con (AccountRepository, BookRepository, ReaderRepository, TicketRepository) kế thừa trọn vẹn cơ chế I/O mà không phải viết lại luồng đọc/ghi file.
  • An toàn kiểu dữ liệu (Type-Safety): Ràng buộc <T extends Serializable> đảm bảo mọi thực thể lưu xuống data/*.dat đều hỗ trợ tuần tự hóa hợp lệ tại thời điểm biên dịch.
  • Tự động khởi tạo thư mục: Tự gọi mkdirs() nếu thư mục data/ chưa tồn tại.

// Mã hóa mật khẩu một chiều bằng SHA-256 trong PasswordUtil public static String hashPassword(String rawPassword) { try { MessageDigest md = MessageDigest.getInstance("SHA-256"); byte[] hash = md.digest(rawPassword.getBytes(StandardCharsets.UTF_8)); StringBuilder hex = new StringBuilder(); for (byte b : hash) hex.append(String.format("%02x", b)); return hex.toString(); } catch (NoSuchAlgorithmException e) { throw new RuntimeException(e); } } // Kiểm tra đăng nhập trong AuthService public Librarian login(String username, String password) throws AuthenticationException { Librarian acc = accountRepo.findByUsername(username); if (acc == null || !acc.getPasswordHash().equals(PasswordUtil.hashPassword(password))) { throw new AuthenticationException("Tên đăng nhập hoặc mật khẩu không đúng!"); } return acc; }

🧰 Hệ thống 7 Lớp Tiện ích (Package utils)

  • PasswordUtil: Băm mật khẩu SHA-256 trước khi lưu xuống accounts.dat.
  • Validator: Kiểm tra Regex Email, Số điện thoại 10 chữ số, chuỗi rỗng và số nguyên dương; ném InvalidDataException hoặc InvalidQuantityException.
  • IdGenerator: Tự động sinh mã định danh duy nhất tăng dần (BK001, RD001, TK001, LB001).
  • InputHelper: Đọc dữ liệu Console an toàn, tự động bắt NumberFormatException và DateTimeParseException để yêu cầu nhập lại.
  • DateFormatter & MoneyFormatter: Định dạng ngày dd/MM/yyyy và tiền tệ #,### VNĐ.
  • TextUtils: Chuẩn hóa chuỗi tìm kiếm không dấu tiếng Việt.

15 Đánh giá Kết quả: Ưu điểm & Hạn chế Tồn tại
Tổng kết & Đánh giá

🌟 Ưu điểm Nổi bật của Hệ thống

  • Kiến trúc sạch, dễ bảo trì: Tách biệt hoàn toàn giao diện Console khỏi nghiệp vụ và lưu trữ dữ liệu.
  • Áp dụng chuẩn OOP & Design Pattern: Kế thừa đa cấp (User $\rightarrow$ Reader), Strategy Pattern cho chính sách phạt, Generic Repository và Dependency Injection.
  • An toàn dữ liệu cao: Kiểm soát chặt chẽ mọi trường hợp ngoại lệ, đảm bảo tính nguyên tử khi mượn nhiều sách và ràng buộc khóa ngoại logic trước khi xóa.
  • Sẵn sàng triển khai: Có dữ liệu mẫu tự động (SampleDataService), kịch bản demo và tệp thực thi LibraryApp.jar.

⚠️ Hạn chế Tồn tại

  • Lưu trữ bằng File nhị phân (.dat): Chỉ phù hợp với quy mô dữ liệu vừa và nhỏ, chưa hỗ trợ truy vấn phức tạp diện rộng hay truy cập đồng thời đa người dùng (Concurrency).
  • Giao diện dòng lệnh (Console): Trực quan ở mức bảng văn bản, chưa hỗ trợ thao tác chuột hay hiển thị biểu đồ thống kê đồ họa.
  • Phân quyền đơn cấp: Hiện tại mới hỗ trợ vai trò Thủ thư (Librarian) vận hành hệ thống, chưa có cổng đăng nhập riêng cho Độc giả tự tra cứu trực tuyến.
